## 2. 否定清单：这些不能做，理由如下

### ❌ 否定 1：抠图贴背景，然后声称"提升了**光照**鲁棒性"

**这是最危险的一条，也是你上一轮问的。**

**理由**：PlantVillage 的叶片是**实验室受控光照**下拍的。贴到野外背景上，**叶片的颜色统计仍然是实验室的**。你补的是**背景多样性**，不是**光照多样性**。

- ✅ 能回答："模型对**背景**变化的鲁棒性"
- ❌ **不能**回答："模型对**光照**变化的鲁棒性"

**除非在贴完之后再施加光照变换**——那就要明说做了两步，且背景成了额外变量。

### ❌ 否定 2：用 GVLiD 的 `Lighting` 字段做光照域

**理由**：**实测发现该元数据与图片 EXIF 不一致**（拍摄日期差 16 个月、设备型号不符）。

| | metadata.json 声称 | 图片真实 EXIF |
|---|---|---|
| 拍摄日期 | 2023-06-15（3,477 条全同一天） | **2024-10-27** |
| 设备型号 | Redmi Note 10 5G（100%） | **samsung SM-A037F** |

而且 EXIF 时刻**全部落在 11:36–12:03 半小时内**——不可能同时存在 sunny/overcast/partly cloudy 三种真实光照域。

**用它做光照域 → 域划分是随机的 → 会得到"没有域间隙"的假结论。**
（但这个负结果可以写进论文的"相关工作"，作为"为什么必须自建光照域"的论据。）

### ❌ 否定 3：只用 PlantVillage 训练 + 真实数据测试

**理由**：这是 **Mohanty 2016 的老问题**（99.35% → 31.4%），被做烂了，且与四元数无关。没有新意。

### ❌ 否定 4：只做"四元数 vs 普通 MobileNet"的精度对比，不做跨光照评估

**理由**：那就是普通的架构对比。而且综述 Altamirano-Gómez 2023 明确把
*"四元数与实数架构的比较是否公平"* 列为**未解决**问题——**不做参数量对齐的对照组，结论会被一句话打掉**。

### ❌ 否定 5：试图做"真实大田光照域泛化"

**理由**：**数据不存在**。5 个候选数据集的元数据全部实测核对过，**没有一个有可信的逐图光照标签**。
硬做只能靠自动光照分类器，而那个分类器有"靠背景判断光照"的致命问题。

### ❌ 否定 6：把 YOLO 也四元数化，做全四元数 pipeline

**理由**：① 已验证 C2f 的 `chunk(2,1)` 会**静默**破坏四元数结构，工程量与风险大；
② 与核心研究问题（分类器的光照泛化）**无关**，纯粹是工程量堆砌。

## 3. 可行路线

### 🥇 路线 A：PlantDoc + 合成光照域 + 四元数 MobileNet（单阶段分类）

**这是最小、最快、最可控的路线，我推荐从这里起步。**

| 项 | 内容 |
|---|---|
| **数据** | PlantDoc 裁剪版（2,578 张，已按框裁好） |
| **光照域来源** | **合成光照变换**（黑体辐射色温 + 强度 + gamma/对比度） |
| **网络** | 四元数 MobileNetV3-Small vs 普通 vs **参数量对齐的普通版**（三组） |
| **评估** | 域 A 训练 → 域 B 测试；报各域性能 + 衰减幅度 + 最差域 |
| **架构** | 单阶段分类（不涉及 YOLO） |

**执行步骤**：

1. **写光照变换函数**（色温用黑体辐射→RGB 增益；强度；gamma）
2. **域间隙预实验**（半天）：同一批图施加变换 A / B，A 训 B 测，**看掉点幅度**
   - 掉点明显（≥10%）→ 继续
   - 掉点很小 → 加大变换强度；仍不行 → 说明课题测不出东西，转路线 D
3. 生成光照域数据集（4 个域：暖/冷 × 强/弱，或连续扫描）
4. 训练三组网络（四元数 / 普通 / 参数量对齐普通），**每组 ≥3 个随机种子**
5. 报告：分域性能 + 衰减曲线 + 最差域 + 统计显著性
6. 消融：光照轴分别扫描（色温单独 vs 强度单独），验证 3 节的**理论预测**

**评估**：

| | |
|---|---|
| **优点** | ✅ 光照标签 **100% 准确**（是你自己施加的）<br>✅ 参数**完全可控**，能画**连续衰减曲线**（真实数据做不到）<br>✅ 文献空白，没人做过<br>✅ 成本最低，一天内能出预实验结果<br>✅ 无 YOLO 框污染问题 |
| **缺点** | ⚠️ 合成 ≠ 真实，**外部效度弱**（要在论文里诚实讨论）<br>⚠️ 只能模拟**全局颜色变换**，阴影/方向性模拟不了 |
| **工作量** | ★★☆☆☆（低） |
| **可行性** | ★★★★★ |
| **能否撑起毕设** | ✅ 可以，但偏"方法研究"，缺少"工程实现"成分 |

---

### 🥈 路线 B：路线 A + 两阶段 pipeline（完整版）

**在路线 A 之上加回 YOLO，补上毕设需要的"设计与实现"成分。**

| 项 | 内容 |
|---|---|
| **数据** | PlantDoc（检测 + 分类） |
| **光照域** | 同路线 A（合成） |
| **架构** | **YOLO（普通卷积）画框 + 四元数 MobileNet 识别** |
| **评估** | ① 分类器的跨光照实验（**用 ground-truth 框**，避开 YOLO 漏检偏置）<br>② **检测器**在各光照域的 recall/mAP（单独报）<br>③ 端到端（YOLO 框 + 分类器） |

**执行步骤**：

1. 完成路线 A 的全部步骤
2. 训一个 YOLOv8n 检测器（普通卷积，**不要四元数化**）
3. 报告检测器在合成光照域上的 recall / mAP —— **这本身就是一个独立结果**（检测器怕不怕光照？）
4. 报端到端数字，并**说明它与①的差距来自哪里**（这是 YOLO 框污染陷阱的正确处理方式）

**评估**：

| | |
|---|---|
| **优点** | ✅ 有"设计+实现"，符合本科毕设形态<br>✅ 多一个分析维度（检测器 vs 分类器谁更怕光照）<br>✅ 两阶段有文献背书（HODRF, Iwano et al. AGRETA 2024） |
| **缺点** | ⚠️ 端到端评估里的检测器偏置要小心处理<br>⚠️ 工作量约为路线 A 的 1.5–2 倍 |
| **工作量** | ★★★☆☆（中） |
| **可行性** | ★★★★☆ |
| **能否撑起毕设** | ✅✅ **最完整的形态** |

---

### 🥉 路线 C：路线 A + 人工标注真实光照做验证（外部效度）

**如果路线 A 的预实验结果好，且你有时间，可以用真实数据做一次外部验证。**

| 项 | 内容 |
|---|---|
| **数据** | PlantDoc 或 FieldPlant（FieldPlant 更大，5,170） |
| **光照域** | **人工标注**（4 类，先标 200 张试） |
| **评估** | 把路线 A 得到的结论拿到真实标注域上复验 |

**执行步骤**：

1. **先标 200 张（1 小时）**，分 2 组，训小模型测掉点
   - **掉点明显** → 标完 5,000 张（约 4 小时）
   - **掉点很小** → **放弃这条路线**，只保留路线 A/B
2. 标注时找第二个人标 10%，报**标注者间一致性（kappa）**
3. 用标注好的真实光照域复验路线 A 的结论

**评估**：

| | |
|---|---|
| **优点** | ✅ 真实数据，**外部效度强**<br>✅ 与路线 A 结合 = "**合成揭示机制 + 真实检验效度**"，这是最有说服力的设计 |
| **缺点** | ⚠️ **可能标完发现没有域间隙**（所以必须先做 200 张预实验）<br>⚠️ 标注主观，需报一致性<br>⚠️ 工作量不确定 |
| **工作量** | ★★★★☆（高，且不确定） |
| **可行性** | ★★★☆☆（取决于预实验） |
| **能否撑起毕设** | ✅ 作为路线 A/B 的**加强**，不建议单独做 |

### 备选路线 D：转向"背景域泛化"（如果光照路线走不通）

**这不是技术上的首选，但要在路线 A 预实验失败时留着。**

| 项 | 内容 |
|---|---|
| **问题** | 四元数卷积对**背景变化**（而非光照）的泛化能力如何？ |
| **数据** | PlantVillage `segmented` 叶片 + PlantDoc 野外背景合成 |
| **理由** | 「抠图贴背景」这条路**成熟、能做、可控**，只是**不能回答光照问题**——那就把问题改成背景 |
| **风险** | 方法不新（Benabbas 2024 已做过分类版），**必须靠四元数这个角度撑新意** |

## 4. 推荐与决策树

### 推荐组合

> **主路线 = A → B**（先做 A 的预实验，通过后扩成 B 的完整版）
> **可选加强 = C**（A/B 的预实验通过、且时间富余时）

### 决策树

```
第 1 步：写光照变换函数 + 域间隙预实验（半天，成本最低）
   │
   ├─ 掉点 ≥10%  ──→ 路线 A 成立
   │                    │
   │                    ├─ 时间够 → 扩成路线 B（加 YOLO，完整毕设）
   │                    └─ 时间更多 + 200张标注掉点也明显 → 加路线 C
   │
   └─ 掉点 <5%   ──→ 加大变换强度重试
                        │
                        ├─ 仍 <5%  ──→ 光照路线测不出东西
                        │               → 转路线 D（背景域泛化），题目相应调整
                        │
                        └─ 变明显了 ──→ 按上面走
```

### 三个必须先做的动作（按顺序，一天内能完成前两个）

| 顺序 | 动作 | 判据 | 成本 |
|---|---|---|---|
| **1** | 写光照变换函数（色温 + 强度 + gamma） | 能生成视觉上合理的变换图 | 2 小时 |
| **2** | 域间隙预实验：A 域训 → B 域测 | **掉点 ≥10%** 才继续 | 半天 |
| **3** | 标 200 张真实光照（并行做） | **掉点 ≥10%** 才走路线 C | 1.5 小时 |

## 5. 一页话总结

> **能做的**：路线 **A**（合成光照域 + 四元数 MobileNet，最小可控）、
> 路线 **B**（A + 两阶段 pipeline，最完整的毕设形态）、
> 路线 **C**（A/B + 真实标注光照验证，最强的说服力但工作量不确定）。
>
> **不能做的**：抠图贴背景声称提升**光照**鲁棒性（补的是背景不是光照）、
> 用 GVLiD 光照标签（元数据与 EXIF 不符）、只做精度对比不做跨光照评估（缺参数量对齐对照组）、
> 追求真实大田光照域（数据不存在）、YOLO 也四元数化（有静默坑且与问题无关）。
>
> **最先做的一件事**：**写光照变换 + 测域间隙**。
> 这一步半天，成本最低，**但决定整个课题能不能成立**——
> 如果合成的光照域造不出性能差距，后面所有工作都是白做。
